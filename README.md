# TBEDU LMS — корпоративная система обучения

Система обучения по охране труда с тремя кабинетами: администратор, руководитель, сотрудник.

Это версия 2.0 — переписанный прототип. Раньше всё работало в одном браузере и хранилось в его памяти. Теперь это обычное веб-приложение: сервер, база данных и сайт, который открывается с любого устройства.

---

## Что умеет система

**Сотрудник** видит назначенное ему обучение, изучает материал (текст, изображения, видео, слайды, трансляции), проходит тест, получает разбор ошибок с объяснениями и сертификат.

**Руководитель** создаёт обучение, добавляет модули с материалом и вопросами, назначает обучение сотрудникам или целым подразделениям, видит результаты и тех, кому нужна помощь.

**Администратор** управляет пользователями и правами, настраивает интерфейс, подключает ИИ-помощника и интеграцию с 1С, смотрит журнал действий.

---

## Главное, что нужно понять про версии

Это устройство системы, а не техническая деталь: от него зависит, сбросится ли прогресс у сотрудников.

Когда вы правите модуль, система смотрит, **что именно** изменилось.

| Что изменили | Новая версия | Что будет с сотрудниками |
|---|---|---|
| Название лектора, главу, код доступа | Не создаётся | Ничего не меняется, прогресс сохраняется |
| Текст материала, вопрос, правильный ответ, проходной балл | Создаётся | Кто уже сдал — увидит «Требует повторного прохождения» |

Перед публикацией система прямо пишет, что произойдёт. Вы узнаёте это **до** того, как нажмёте «Опубликовать», а не после.

Прежние результаты при этом не пропадают — они остаются в истории и привязаны к той версии, которую человек проходил.

## Как запустить

### Вариант 1: через Docker (проще всего)

Нужен установленный Docker.

```bash
# 1. Создайте файл .env с секретами
cat > .env <<'EOF'
SESSION_SECRET=замените-на-случайную-строку-не-короче-32-символов
ENCRYPTION_KEY=другая-случайная-строка-не-короче-32-символов
BOOTSTRAP_ADMIN_LOGIN=admin
BOOTSTRAP_ADMIN_PASSWORD=придумайте-пароль
SEED_DEMO=true
EOF

# 2. Запустите
docker compose up -d

# 3. Откройте в браузере
# http://localhost:3000
```

Система сама создаст базу, применит миграции и заведёт администратора.

### Вариант 2: вручную

Нужны Node.js 20 или новее и PostgreSQL 14 или новее.

```bash
# 1. Установите зависимости
npm install

# 2. Настройте подключение
cp .env.example .env
# откройте .env и укажите DATABASE_URL, SESSION_SECRET, ENCRYPTION_KEY

# 3. Создайте таблицы и заполните справочники
npm run db:migrate
npm run db:seed

# 4. Соберите и запустите
npm run build
npm start
```

Для разработки вместо шага 4:

```bash
npm run dev
```

Откроется два процесса: сервер на порту 3000 и сайт на порту 5173. Работайте с `http://localhost:5173` — запросы к серверу он перенаправляет сам.

## Первый вход

После `npm run db:seed` создаётся один администратор:

- логин: `admin` (или тот, что указан в `BOOTSTRAP_ADMIN_LOGIN`)
- пароль: из `BOOTSTRAP_ADMIN_PASSWORD`

**При первом входе система потребует сменить пароль.** Это не придирка: пароль из файла настроек попадает в историю команд и в репозиторий, поэтому постоянным он быть не может.

Если в `.env` указано `SEED_DEMO=true`, дополнительно создаются демо-данные:

| Логин | Пароль | Кто |
|---|---|---|
| `manager` | `manager123` | Руководитель |
| `petrov`, `sidorov`, `kuznetsov` | `employee123` | Сотрудники |

Демо-данные нужны, чтобы посмотреть систему в работе. Перед боевым запуском поставьте `SEED_DEMO=false`.


## Перенос данных из прототипа

Данные старой версии лежат в памяти браузера. Чтобы их забрать:

1. Откройте старую страницу руководителя в браузере.
2. Нажмите F12, перейдите на вкладку «Console».
3. Выполните: `copy(JSON.stringify(localStorage))`
4. Вставьте скопированное в файл `legacy.json`.
5. Выполните `npm run import:legacy -- ./legacy.json`

**Важно про пароли.** Старые пароли перенести невозможно — прототип хранил их в виде, из которого исходный пароль не восстановить и в новый формат не преобразовать. Поэтому всем перенесённым сотрудникам выдаются временные пароли. Скрипт сохраняет их в файл `temp-passwords-ГГГГ-ММ-ДД.csv`.

Раздайте пароли лично, **после раздачи удалите файл**. При первом входе система потребует сменить пароль.

Обучения переносятся как черновики — просмотрите их и опубликуйте вручную.

## Устройство проекта

```
shared/     Общий код: типы, проверки, расчёт версий и прогресса.
            Один и тот же код работает и на сервере, и в браузере,
            поэтому правила не могут разойтись.

backend/    Сервер: API, база данных, проверка прав, интеграции.
            Здесь же проверяются ответы на тесты.

frontend/   Сайт: три кабинета, работает на телефоне и на компьютере.
```

### Почему проверка тестов на сервере

В прототипе правильные ответы приходили в браузер вместе с вопросами, и результат считался там же. Пока всё работало на одном компьютере, это было неважно. Как только система стала доступна по сети, это означало бы, что ответы можно посмотреть заранее.

Теперь сервер выдаёт вопросы **без признака правильности**, принимает ответы и считает результат сам. В браузер правильные ответы попадают только после завершения попытки — в разборе ошибок.

## Настройки (.env)

| Переменная | Зачем | Обязательна |
|---|---|---|
| `DATABASE_URL` | Адрес базы данных | Да |
| `SESSION_SECRET` | Подпись сессий. Не короче 32 символов | Да |
| `ENCRYPTION_KEY` | Шифрование ключей ИИ и данных 1С. Не короче 32 символов | Да |
| `PORT` | Порт (по умолчанию 3000) | Нет |
| `SEED_DEMO` | Создавать демо-данные | Нет |
| `FILE_STORAGE` | `local` или `s3` | Нет |
| `ANTHROPIC_API_KEY` | Запасной ключ ИИ, если не задан в интерфейсе | Нет |

**О `ENCRYPTION_KEY`:** если его поменять, сохранённые ключи ИИ и учётные данные 1С перестанут читаться, их придётся ввести заново. Сохраните этот ключ в надёжном месте.
