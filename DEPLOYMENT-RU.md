# Как выложить систему в интернет

Инструкция рассчитана на человека без опыта администрирования серверов. Каждый шаг можно выполнить по порядку, ничего не пропуская.

Всего понадобится около часа.

---

## Что вам нужно приготовить заранее

1. **Банковская карта** — большинство площадок просят её привязать даже для бесплатного тарифа.
2. **Почта** для регистрации.
3. **Два случайных ключа** — сгенерируйте их прямо сейчас и сохраните в надёжном месте (например, в менеджере паролей).

Как сгенерировать ключ:

- **Windows:** откройте PowerShell и выполните
  ```powershell
  [Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Maximum 256 }))
  ```
- **macOS или Linux:** откройте терминал и выполните
  ```bash
  openssl rand -base64 32
  ```

Выполните команду **дважды** — получите два разных ключа. Первый назовём `SESSION_SECRET`, второй — `ENCRYPTION_KEY`.

> **Сохраните `ENCRYPTION_KEY` особенно надёжно.** Им шифруются ключи ИИ-помощника и пароли от 1С. Если потеряете — эти данные придётся вводить заново.

## Вариант А: развёртывание на Render (рекомендуется)

Render — площадка, где можно запустить и приложение, и базу данных. Есть бесплатный тариф для проверки.

### Шаг 1. Загрузите код на GitHub

1. Зайдите на [github.com](https://github.com) и зарегистрируйтесь.
2. Нажмите зелёную кнопку **New** — создастся новый репозиторий.
3. Назовите его `tbedu-lms`, выберите **Private**, нажмите **Create repository**.
4. На открывшейся странице найдите блок «…or push an existing repository».
5. В папке с проектом выполните команды оттуда. Выглядят они примерно так:

```bash
git init
git add .
git commit -m "Первая версия"
git branch -M main
git remote add origin https://github.com/ВАШ-ЛОГИН/tbedu-lms.git
git push -u origin main
```

> Файл `.env` в репозиторий не попадёт — он указан в `.gitignore`. Так и должно быть: секреты в репозитории хранить нельзя.

### Шаг 2. Зарегистрируйтесь на Render

Откройте [render.com](https://render.com), нажмите **Get Started** и войдите через GitHub. Разрешите доступ к репозиторию `tbedu-lms`.

### Шаг 3. Создайте базу данных

1. В панели Render нажмите **New +** → **Postgres**.
2. Заполните:
   - **Name:** `tbedu-db`
   - **Database:** `tbedu`
   - **Region:** Frankfurt (ближайший к Казахстану)
   - **Plan:** Free (для проверки) или Starter (для работы)
3. Нажмите **Create Database**.
4. Подождите 2–3 минуты, пока статус станет **Available**.
5. На странице базы найдите строку **Internal Database URL** и скопируйте её. Она начинается с `postgres://`.

> Бесплатный тариф базы **удаляется через 30 дней**. Для реальной работы берите платный — иначе однажды все данные исчезнут.

### Шаг 4. Создайте приложение

1. **New +** → **Web Service**.
2. Выберите репозиторий `tbedu-lms`.
3. Заполните:
   - **Name:** `tbedu`
   - **Region:** тот же, что у базы (Frankfurt)
   - **Branch:** `main`
   - **Runtime:** Docker
   - **Plan:** Free или Starter
4. Пока **не нажимайте** Create.

### Шаг 5. Впишите настройки

Прокрутите до раздела **Environment Variables** и добавьте по одной:

| Ключ | Значение |
|---|---|
| `DATABASE_URL` | Internal Database URL из шага 3 |
| `SESSION_SECRET` | Первый ключ, который вы сгенерировали |
| `ENCRYPTION_KEY` | Второй ключ |
| `NODE_ENV` | `production` |
| `BOOTSTRAP_ADMIN_LOGIN` | `admin` |
| `BOOTSTRAP_ADMIN_PASSWORD` | придумайте пароль не короче 12 символов |
| `BOOTSTRAP_ORG_NAME` | название вашей организации |
| `SEED_DEMO` | `false` |

> `SEED_DEMO=false` — обязательно. Иначе в боевой системе появятся демо-сотрудники с известными паролями.

### Шаг 6. Запустите

Нажмите **Create Web Service**. Первая сборка занимает 5–10 минут.

Следите за вкладкой **Logs**. Когда появится строка

```
TBEDU LMS 2.0.0 слушает http://0.0.0.0:10000
```

— система работает.

### Шаг 7. Примените миграции

Миграции применяются автоматически при старте, если вы используете `docker-compose.yml`. На Render выполните их вручную один раз:

1. На странице приложения откройте вкладку **Shell**.
2. Выполните:

```bash
node backend/dist/scripts/migrate.js
node backend/dist/scripts/seed.js
```

Вы увидите отчёт о созданных правах, ролях и администраторе.

### Шаг 8. Проверьте, что всё работает

1. Откройте адрес вида `https://tbedu.onrender.com/api/health`.
   Должен прийти ответ со словом `"ok"`.
2. Откройте `https://tbedu.onrender.com` — увидите страницу входа.
3. Войдите под `admin` и паролем из шага 5.
4. Система попросит сменить пароль — смените.

### Шаг 9. Свой домен (необязательно)

1. Купите домен у любого регистратора.
2. В Render: **Settings** → **Custom Domain** → **Add Custom Domain**.
3. Введите домен, например `obuchenie.вашафирма.kz`.
4. Render покажет, какую запись добавить у регистратора. Добавьте её.
5. Подождите от 10 минут до нескольких часов.

Сертификат HTTPS Render выпустит сам.

## Вариант Б: развёртывание на своём сервере

Подходит, если сервер должен стоять внутри организации.

### Что нужно

- Сервер с Ubuntu 22.04 или новее, не менее 2 ГБ оперативной памяти
- Доступ по SSH
- Установленный Docker

### Шаги

```bash
# 1. Установите Docker
curl -fsSL https://get.docker.com | sh

# 2. Скопируйте проект на сервер и перейдите в его папку
cd /opt/tbedu

# 3. Создайте файл с настройками
nano .env
```

Впишите:

```
SESSION_SECRET=ваш-первый-ключ
ENCRYPTION_KEY=ваш-второй-ключ
BOOTSTRAP_ADMIN_LOGIN=admin
BOOTSTRAP_ADMIN_PASSWORD=ваш-пароль
BOOTSTRAP_ORG_NAME=Название организации
SEED_DEMO=false
```

Сохраните: `Ctrl+O`, `Enter`, `Ctrl+X`.

```bash
# 4. Запустите
docker compose up -d

# 5. Посмотрите, что происходит
docker compose logs -f app
```

Система сама применит миграции и создаст администратора.

Откройте `http://адрес-сервера:3000`.

### Настройка HTTPS

Без HTTPS пароли идут по сети открытым текстом. Для системы, доступной извне, это обязательный шаг.

```bash
# Установите Caddy — он получает сертификаты сам
apt install -y debian-keyring debian-archive-keyring apt-transport-https
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | tee /etc/apt/sources.list.d/caddy-stable.list
apt update && apt install caddy

# Настройте
nano /etc/caddy/Caddyfile
```

Впишите (замените домен на свой):

```
obuchenie.вашафирма.kz {
    reverse_proxy localhost:3000
}
```

```bash
systemctl restart caddy
```

Caddy получит сертификат автоматически.

## Резервное копирование

Без резервных копий любая поломка означает потерю всех результатов обучения. Настройте их сразу, а не «потом».

### На Render

Платные тарифы базы делают копии сами. Проверьте: страница базы → **Backups**.

### На своём сервере

Создайте файл `/opt/tbedu/backup.sh`:

```bash
#!/bin/bash
# Резервная копия базы данных TBEDU
DATE=$(date +%Y-%m-%d-%H%M)
DIR=/opt/tbedu/backups
mkdir -p $DIR

docker compose -f /opt/tbedu/docker-compose.yml exec -T db \
  pg_dump -U tbedu tbedu | gzip > $DIR/tbedu-$DATE.sql.gz

# Копии старше 30 дней удаляем
find $DIR -name "tbedu-*.sql.gz" -mtime +30 -delete

echo "Копия создана: $DIR/tbedu-$DATE.sql.gz"
```

```bash
chmod +x /opt/tbedu/backup.sh

# Запуск каждую ночь в 3:00
crontab -e
```

Добавьте строку:

```
0 3 * * * /opt/tbedu/backup.sh >> /var/log/tbedu-backup.log 2>&1
```

### Как восстановить из копии

```bash
gunzip -c /opt/tbedu/backups/tbedu-2026-01-15-0300.sql.gz | \
  docker compose exec -T db psql -U tbedu -d tbedu
```

> **Проверьте восстановление хотя бы раз.** Копия, которую ни разу не разворачивали, — это копия, про которую неизвестно, работает ли она.

## Что делать, если не работает

### Страница не открывается

Посмотрите журнал:
- Render: вкладка **Logs**
- Свой сервер: `docker compose logs app`

### В журнале «Нет соединения с базой данных»

Проверьте `DATABASE_URL`. На Render должен использоваться **Internal** адрес, а не External.

### «В production обязательна переменная SESSION_SECRET»

Вы не заполнили секреты или оставили значения из примера. Вернитесь к шагу 5.

### «SESSION_SECRET должна содержать не менее 32 символов»

Ключ слишком короткий. Сгенерируйте заново командой из начала инструкции.

### Забыт пароль администратора

На сервере выполните:

```bash
docker compose exec db psql -U tbedu -d tbedu \
  -c "UPDATE users SET must_change_password = true WHERE login = 'admin';"
```

Затем задайте новый пароль через скрипт сида — или, если администраторов несколько, сбросьте пароль из интерфейса другого администратора.

### Приложение «засыпает» на бесплатном тарифе

Бесплатный тариф Render останавливает приложение после 15 минут без запросов, а следующий запрос ждёт около минуты. Для реальной работы нужен платный тариф.

## Что сделать после запуска

- [ ] Сменить пароль администратора
- [ ] Поставить `SEED_DEMO=false` и удалить демо-пользователей, если они создавались
- [ ] Настроить резервное копирование и **проверить восстановление**
- [ ] Подключить HTTPS
- [ ] Создать подразделения и должности
- [ ] Завести руководителей и назначить им зоны ответственности
- [ ] Загрузить сотрудников (вручную или из 1С)
- [ ] Создать первое обучение и проверить его на себе
- [ ] Сохранить `SESSION_SECRET` и `ENCRYPTION_KEY` в надёжном месте
